Product Definition

What exec is, who it's for, and what it will and won't do.

In one line

exec takes code, runs it safely in Docker, and sends back the output.

Problem

Running someone's code directly on your computer is dangerous. It could delete files, use the network, or freeze the machine.

So this constraint makes it clear for a need for a small service that runs code in a locked box and returns the result.

Users

WhoWhat they want
The developerOne simple API call: send code, get output.

Features

#FeatureDetails
F1Run codePOST /api/v1/execute with language + code + stdin (optional). Returns stdout, stderr, exit code, time.
F2Safe sandboxNo network, read-only code, 256 MB RAM, 1 CPU, 128 processes, no special permissions.
F3LogsEvery run gets a short ID. Logs show start, end, status and time.

Non-goals (won't do)

  • No public deployment. Runs on your own machine only.
  • No login or users.
  • No rate limit or concurrency cap.
  • No saving code. Nothing is stored after a run.
  • No internet from inside the user's program.
  • No live output streaming. Output comes back once the run ends.
  • No multi-file projects. One file per run.
